# План Code Review для модуля расчета скидок (discount.py)

### 1. Цели ревью
* **Точность расчетов:** Исключить округления в пользу клиента, ведущие к финансовым потерям.
* **Защита от фрода:** Проверить логику на невозможность получения отрицательной стоимости или обхода лимитов.
* **Корректность бизнес-логики:** Гарантировать правильный порядок применения скидок (базовая -> промокоды -> программа лояльности).

### 2. Измеримые критерии качества
* **Магические числа:** Полное отсутствие хардкода (коэффициенты `0.85`, `0.70` и суммы `15000`, `500` должны быть вынесены в конфигурацию или константы).
* **Валидация данных:** Наличие проверок входных параметров (`cart_sum >= 0`, `tier` строго целое число).
* **Покрытие тестами:** Покрытие кода юнит-тестами должно быть строго > 80%.

### 3. Участники и роли
* **Автор кода (Developer):** Пишет код, исправляет замечания.
* **Рецензент (Tech Lead / Senior Analyst):** Проверяет архитектурное соответствие и бизнес-логику.
* **QA Инженер:** Анализирует граничные условия применения скидок.

### 4. Раздел эскалации споров
В случае возникновения разногласий между разработчиком и рецензентом:
1. Проводится обсуждение в комментариях к Pull Request с привлечением Product Owner для уточнения требований.
2. Итоговое архитектурное решение принимает Tech Lead.
